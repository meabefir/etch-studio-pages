# Etch · Hatching Studio

A browser-based 3D line-hatching editor. Models are processed on your device. The included small local server serves the app and reads local OBJ/GLB paths for scene reloading. No accounts or model uploads to external services are required.

## Open the app

Use the online editor at **https://meabefir.github.io/etch-studio-pages/**. Models are processed in your browser. When opening a saved scene, reselect imported model files through the file picker. Online scenes and presets are stored separately from the local copy.

Run the included local copy:

1. Extract the ZIP into a folder.
2. With Node.js installed, double-click **Start Etch.cmd** on Windows.
3. Open **http://127.0.0.1:4173**. Keep the server window open while using the app.

On other platforms, run `node server.mjs` in this folder and open the same address. Serve the `dist` folder through HTTP; opening `index.html` directly cannot start the rendering workers.

## GitHub Pages development

This repository preserves the original project's commit history and folder layout. Continue editing the app in `dist/`; run `node server.mjs` or **Start Etch.cmd** for the local editor. Commit and push changes to `main` to update the online editor automatically.

GitHub Pages publishes `main` from the repository root. The root `index.html` opens `dist/`, so the live app uses the same files as the local server. `.nojekyll` disables Jekyll processing. The local server is used only on your computer; GitHub Pages serves static files. Browser saves and presets keep the same site address and remain available.

## Workflow

- **Import model** accepts a full local **OBJ** or **GLB** path, or lets you browse for a file. You can also drag files onto the drawing. Paths may include spaces; quotes copied from Windows Explorer are removed automatically.
- Click a model or its scene entry to select it. Use the gizmo to move, rotate, or scale it; edit exact values in **Selection**.
- Press **W**, **E**, or **R** for move, rotate, or scale. Choose local or world axes in the toolbar.
- Drag to orbit, hold and drag the mouse wheel to pan, and scroll to zoom. Hold the **right mouse button** to enter free flight: move the mouse to look, **WASD** to move, **Q/E** down/up, and **Shift** to move faster. Scrolling while flying adjusts movement speed. Release right mouse or press **Escape** to return to orbit; losing focus also exits. These controls work in the main view and the sigil editor. Flight updates only the active scene camera. **F** frames the selected model, or the full scene if nothing is selected. **Escape** clears selection.
- The corner **Camera orientation** widget follows the active view. Click **±X**, **±Y** or **±Z** to look along that axis toward the selected model, fitting it in view. With no model selected it fits the visible scene. The arrows underneath roll the camera around its viewing direction in **15° increments**. Alignment and roll update only the active camera and are stored with saved scenes.
- The bottom **Grid** toggle displays an infinite ground plane at Y = −2.3. It respects model depth in shaded and hatched views, and fades radially between 36 and 60 scene units from the camera's position over the plane. It follows the view without a finite grid boundary. Grid spacing increases as the ground appears smaller on screen, including in orthographic views; the active camera's clipping range still applies.
- Use the visibility button to hide objects. **Delete** removes the selected model or light.
- Add **Sun** or **Point** lights. Select a light to edit its position, intensity, and color. A sun also has an aim target; a point light has configurable distance falloff. Up to eight lights are supported. The top **Light icons** button toggles the source icons and sun direction arrows. Sources outside the view appear as edge icons; click an icon to select its light. **Frame** with a light selected includes the source and its target. Selected suns default to **Aim light**, placing the axis gizmo at their target; switch to **Move light** to reposition the source. Aim changes update the lighting and hatching.
- The **CAMERAS** category always contains at least one camera. Selecting a camera makes it active. Orbiting, panning, zooming, framing and resetting the view update that camera only. **Add camera** copies the current view and activates the new camera, preserving the previous one. Selecting a model or light keeps the same active camera. Deleting the active camera switches to another; the final camera cannot be deleted.
- Select a camera to edit its position, aim target, projection, field of view and near/far clipping. Projections include **Perspective**, **Orthographic**, a circular equidistant **Fisheye** (10–170°), **Barrel**, and **Pincushion** distortion. Orthographic uses view height instead of FOV; the distortion lenses have a strength control. Lens distortion affects both shading and the surface direction field before hatching, preserving constant final stroke widths.
- The **Hatching setup** dropdown chooses global settings or a model's separate settings. Global settings affect models that inherit them. Change line color, constant thickness, shadow and light spacing (both allow **1 px**), maximum stroke length, curvature influence, direction rotation, lighting, depth spacing, cavity emphasis, and cross-hatching. Shadow spacing cannot exceed light spacing; changing either adjusts the other when needed.
- OBJ files with multiple named objects or groups load as separate selectable models. They retain their relative positions and each has its own transform pivot. Scene saves store the file path and the part reference, so reloading restores each part once. Older scene saves that grouped the entire OBJ remain compatible. GLB imports remain grouped.
- Select a model and enable **Use separate hatching setup**, then **Edit this object’s hatching**. Its style begins as a copy of the global setup. You can apply any built-in or saved preset, then customize it independently. Switching off the checkbox returns to global inheritance. **Render detail** is always global; an object's paper tint applies to its visible surface.
- The **Toon shading** tab offers **Hatching only**, **Toon only**, and **Toon + hatching**. Toon shading maps the surface normal against the average of enabled light directions; each direction is normalized before averaging, so adding an identical light does not double the tone. Point lights use the direction from each surface point to the source. Hidden or zero-output lights do not contribute. In **Color ramp**, add/remove stops, drag them horizontally, and edit their colors and positions from 0 (shadow) to 1 (light). **Linear** blends colors between stops; **Constant** creates flat color bands. Arrow keys move a selected stop, Shift uses larger steps, and Home/End move to the limits. Choose a global or per-object setup using **Toon setup**. Toon and hatching have independent scopes and object overrides. Enable **Use separate toon setup** for an object, or edit its toon values to create an override; switch it off to inherit the global toon settings. Hatching presets and hatching resets leave the rendering mode, ramp colors, stop positions and ramp blending unchanged. Outlines remain available in all three modes. Ramps and shading modes are stored with scene saves, and PNG exports use the same shading. Older saved scenes retain their original per-object toon styling.
- In **Toon shading → Color ramp preset**, choose **Studio**, **Graphite**, **Moonlight**, **Verdigris**, **Forest**, **Ember**, **Rose quartz**, **Porcelain**, or **Cyber glow**. Choosing a ramp applies its colors, stop positions and Linear/Constant blending to the current global or per-object toon setup. **Load ramp** reapplies it after edits. Rendering style and hatching settings stay unchanged. **Save ramp** stores a named custom ramp in this browser's local storage; saved entries appear under **Saved ramps**, and saving the same name updates one. Ramps persist across reloads, independently of scene and hatching presets. Each browser profile and site address has its own list.
- Enable **Hard contours** in **Hatching** to add lines along shared mesh edges whose face angle is above **Face angle threshold** (0–180°). It is off by default. Set **Hard contour thickness** and **Hard contour color** independently of the hatch strokes. Face angles use actual triangle positions, including smooth-normal OBJ/GLB geometry and non-uniform object scaling. Open boundaries remain part of the outer outline. Hidden edges are removed with scene depth; visible contours are calculated first and reserve their space before hatching, so hatch lines stop at them. Settings can be global or per-object and are included in hatching presets, scene saves and PNG exports, including tiled 10K and lens projections.
- Enable the **Outer outline** and choose its thickness and color.
- The separate **Depth outlines** tab adds lines at abrupt depth differences within visible geometry. Enable it and adjust **Depth threshold**, **Minimum depth jump**, line color, constant thickness and opacity. The threshold is relative to the nearer surface's camera distance; the minimum jump is in scene units. **Sampling distance** controls the detection neighborhood, **Slope rejection** suppresses lines on smooth tilted surfaces, **Minimum edge length** filters fragments, and **Edge smoothing** softens pixel steps. **Across object boundaries** includes overlaps between different objects. Its setup dropdown shares the global or per-object hatching setup. Depth settings have individual resets and are included in presets, scenes and PNG exports.
- The **↺** button beside each editable property reverts that property to its app default. Transform axes reset independently; a scale-axis reset does not change the other axes even when scale linking is enabled. Model defaults are position/rotation zero and scale one. Lights reset to their initial sun or point-light values.
- At the top of **Hatching**, choose **Engraving**, **Fine pen**, **Open strokes**, **Woodcut**, **Copperplate**, or **Contour study**. Choosing a preset applies it to the current hatching setup. **Load preset** reapplies the selected preset after changes.
- Click **Save preset**, enter a name, and save. Your named presets appear under **Saved presets** in the same dropdown and persist in this browser's local storage. Saving the same name updates that preset. Presets store hatching, depth-outline and hard-contour settings; scene objects and individual lights are not part of a preset. Browser profiles and site addresses each have their own saved preset list.
- Click **Save scene**, enter a name, and save. The **Saved scenes** dropdown and **Load scene** restore model transforms/visibility/styles, all lights and cameras, the active view, global hatching settings, output dimensions/framing, grid, light icon visibility and view mode. Saving an existing name updates it. Geometry is never embedded in browser storage: imported models contain file references, while study shapes and procedural sigils are regenerated.
- Browsers do not reveal the full path of a browsed or dropped file. When saving, enter that model's path once (Windows Explorer: Shift + right-click → **Copy as path**). The local server checks it and reopens it on future loads. You can also edit **Local model path** in the model's inspector.
- If a model was moved or removed, loading displays an error and **Relink** dialog. Enter its new path, or browse to use a replacement file. Cancelling leaves the current scene intact. Corrected references are saved to the named scene automatically. Browsed replacements need their full path entered on the next save for automatic reloading.
- Use **Export PNG** to open **Image output**. Choose a resolution preset or enter exact **Image width/height**, then **Download PNG**. The button renders the full image and downloads it in one click. Both export buttons stay visible below the preview; **Render full image** lets you inspect the full-size result before downloading. This creates a fresh render at the requested dimensions, independently of the workspace size. Images can be up to **10000 × 10000 pixels**. Choose **Maximum · 10000 px** for a 10K longest side, or enter 10000 for both dimensions for a square 10K image. Large images render geometry in smaller tiles and trace hatch lines across the entire image. Compact geometry buffers reduce memory use. The preview uses up to 1000 pixels on its longest side; the downloaded PNG uses the full chosen dimensions. **Cancel render** stops a pending trace.
- In **Image framing**, use **Fit visible models** or **Fit selected**, drag the preview to pan, scroll to zoom, or edit image scale and frame center. This shifts and enlarges the image window while preserving the active camera's position, angle, field of view, projection and lighting. Geometry outside the workspace crop can be included. Geometry behind the camera, outside its near/far clipping range, or outside a fisheye lens's viewing circle still requires a camera change. **Fit margin** controls padding on the next fit; **Reset framing** restores the original centered camera window. Width and height control the canvas shape independently.
- **Stroke sizing → Match camera view** scales line spacing/thickness with the camera image and export framing. **Exact output pixels** uses the Hatching values directly in the final PNG, including 1-pixel spacing. Lens distortion transports the direction field before tracing, keeping constant stroke widths. Exports omit editing gizmos, the grid, light icons and selection helpers; shaded view also exports at the requested size. **Render detail** controls only the workspace preview, retaining its viewport-based 2× pixel limit.

## Sigil atelier

Choose **Nature / cyber sigil** from **Add object**, or click **Add sigil**. The new **SIGILS** category contains procedural objects with the same scene transforms, visibility and independent hatching as imported models. The pencil beside a sigil's name reopens its separate editor.

- Select a curve and vertex on the left, or grab its marker directly in the viewport. **Editing** chooses the vertex, incoming handle or outgoing handle. Drag a point across the current view plane; it keeps its depth from the camera. Front view moves X/Y, top view moves X/Z, and rotated views follow their current orientation. Axis gizmos are hidden by default; enable **Show axis gizmos** for constrained movement, or enter exact X/Y/Z values. Both Bézier handles on every vertex of the selected curve remain visible above the generated surface. Handle coupling can be **Free**, **Aligned** or **Mirrored**. A complete drag counts as one undo step.
- The **Front / Perspective / Top** menu reapplies a preset every time it is clicked, including the currently selected preset. Choose **Front** again after orbiting to return to a straight front view.
- **Vertex radius** controls local thickness. The active vertex has a small circle outline: grab its edge and drag outward to increase radius or inward to decrease it. The ring follows the vertex in any view; a full drag is one undo step. Focus the ring and use arrow keys for small changes, or Shift + arrow for finer changes. **Add vertex** splits the selected outgoing segment without changing its centerline; at the last vertex it extends the curve. **Add curve** grows a branch from the current vertex.
- An endpoint's **Connect endpoint to pole** menu attaches it to a vertex on another curve. The shared position follows that pole, with optional radius inheritance. Editing a connected endpoint's radius gives it its own radius. Moving a connected vertex moves the shared pole. Deleting a pole detaches its branches at their current position.
- **Motif setup** chooses the selected curve or the **Global motif**. Curves inherit the global motif initially. Enable **Use custom motif for this curve** to copy the global settings and edit that curve independently; switching it off restores inheritance. Shape, symmetry, waves, textures and growth belong to each curve. **Resolution & finish** remain shared by every curve, including custom curves. New curves inherit the global motif.
- Six starting styles are included in **Motif preset**: **Thorn sigil**, **Chrome cybersigil**, **Living vine**, **Continuous sigil**, **Tidal coral**, and **Forged relic**. Choosing a preset applies it to the current motif setup, preserving the curve network, shared resolution and finish. Applying one to a curve automatically enables its custom motif.
- **Save motif** stores the current setup under a name in browser local storage. Saved entries appear under **Saved motifs**; select one to apply it or use **Load motif** to reapply it after editing. Saving the same name updates it. Motifs contain shape, texture and growth settings; save the main scene for curve geometry, per-curve assignments, resolution and finish. Saved lists belong to this browser profile and app address.
- Shape controls include mirror/radial symmetry, cross-section depth and twist, swelling, end taper, pointed/flat/rounded closed caps, junction blending and pole swelling. Other sections control radius ripples, centerline waves, spiral flutes, bark relief, thorn growth and curvature, flattened curled leaves, random seed and material finish. Every property has a reset button.
- Turn off **Live mesh generation** to edit without rebuilding. **Generate mesh** updates the preview manually. **Show editing curves** hides the curves, handles, radius ring and gizmo for an unobstructed mesh view. **Undo/Redo** restore design edits; **Frame** fits the mesh and curves.
- **Samples per segment** controls the baseline curve sampling; bends and long segments receive additional samples to match the surface detail. **Mesh grid resolution** controls surface detail relative to the design's vertex thickness. Sampling is allocated only in small regions around the curves, poles and growth. Moving a vertex far away no longer spreads resolution over an enlarged bounding box; untouched regions retain their detail and empty space between branches is skipped. Higher resolution captures thinner thorns, fine ripples and leaves, but costs more processing time. Increase radius or resolution if a thin feature disappears.
- Enable **Adaptive resolution** in **Resolution & finish** to increase sampling for thin branches, narrowing thorn tips, leaves, ripples, bark, flutes and waves. Thorn/leaf centerlines also receive extra samples. **Adaptive detail fidelity** sets the desired number of samples across small features; **Maximum detail boost** limits how much finer the mesh can become relative to **Mesh grid resolution**. The occupied regions share a lattice to keep their boundaries, junctions and caps closed. The status shows the detail increase and number of local regions; **detail limit reached** refers to the selected boost. A separate occupied-region memory limit reports an error instead of silently lowering the whole mesh's detail. Preview, manual generation, **Apply & return**, and loading a saved scene use the same settings. Turning adaptive mode off keeps sparse local sampling at the manual detail level.
- **Detail budget (samples)** in **Resolution & finish** defaults to **9,000,000** occupied lattice samples. Enter a larger whole number to allow more sampling; the control has no upper limit. It increases the permitted work without changing the requested resolution. The actual available memory still determines what can be generated. The budget is shared by all curves in the sigil, has a default-reset button, and is stored in scene saves.
- Enable **Smooth final mesh** to relax the generated surface while preserving edges sharper than **Sharp angle threshold**. Lower angles protect more details. **Smoothing strength** and **Smoothing passes** control the amount; **Preserve volume while smoothing** reduces shrinkage. Sharp-edge and boundary vertices stay fixed, triangle connectivity and closed caps remain intact, and normals are updated afterward. Smoothing affects the final geometry before curvature analysis, both in the preview and after applying or loading a scene. It is off by default and shared by all curves in that sigil.
- **Apply & return** commits the curves and generated geometry to the scene; **Cancel** discards editor changes. Applying always generates the latest design even when live generation is paused. Save the main scene to preserve the curve network and all its parameters in local storage. Sigils need no source model file.

The generator sweeps variable-radius cubic Bézier curves into sparse blocks of a shared distance field, blends branches at poles, and extracts a closed indexed surface. Blocks outside the swept geometry are rejected before allocation; lattice coordinates remain fixed in world space. Ripples use distance along the curve; parallel-transport frames guide cross sections and growth. Adaptive mode estimates feature sizes, chooses the local sampling scale, and adds centerline samples where needed. The editor's metallic/color controls affect its shaded mesh preview. The main hatching controls determine the illustration's ink and paper.

## How the linework is made

The app welds coincident positions for topology, then separates surface fans at geometric creases sharper than 45°. Normals and curvature are reconstructed from triangle geometry, so imported smooth normals cannot round off a cube. Coplanar regions use one boundary-aligned tangent guide across the whole patch; curved regions fit a local shape operator and smooth their principal curvature field only within the connected surface fan. Smooth attribute seams share the analysis while sharp corners remain separate.

Both hatch families and Flow rotation are defined in the surface tangent plane before projection. Planar guides are projected per pixel, keeping lines straight in perspective; the perpendicular family also follows the actual surface rather than a screen-space 90° turn. Three.js renders visible object IDs, both projected line fields, diffuse lighting, and linear view depth into three offscreen buffers. A worker traces bidirectional streamlines with midpoint integration and checks nearby strokes to maintain spacing. Visible geometric creases stop tracing even when Hard contours is disabled; that toggle controls the extra ink. Depth jumps and silhouettes also stop strokes. New seeds along accepted lines encourage long, parallel families. Lighting controls spacing and visibility, never the geometry field. Lens cameras transport both families before tracing, and tiled PNG exports retain the same crease barriers and directions.

Every hatch stroke uses the same screen-space width. Brightness, distance, and cavity shading vary **spacing**, not stroke thickness. Outer contours are separate complete silhouette loops with their own width. Optional depth outlines detect discontinuities in linear view depth, reject continuing surface slopes, thin the detected edges, and join them into smoothed paths. These lines also have constant screen-space width.

## Practical limits

- This is a procedural engraving approximation. It follows mesh curvature and surface features; it does not reproduce an illustrator's hand-authored artistic choices. Enough mesh detail improves the result; surface normals are reconstructed while preserving geometric creases.
- Material colors, textures, imported lights/cameras, and animation are ignored. GLB supports embedded Draco and Meshopt geometry decoding. External geometry dependencies must be embedded in the GLB.
- Lighting uses diffuse illumination, ambient light, and a screen-space cavity approximation. It does not calculate full shadow maps or global illumination.
- During camera and gizmo interaction the app shows a shaded preview, then retraces the hatching when interaction ends. Dense models and print detail take longer to process.
- Reloading starts a demo scene; use **Load scene** to open a named local save. Scene and preset lists belong to this browser profile and app address.
- Direct path access requires the included local server. A static-hosted copy still supports browser import and scene settings, but must prompt you to reselect model files when loading. The server binds to loopback, accepts only same-origin local requests and only reads explicitly supplied OBJ/GLB paths.
- A current browser with WebGL 2, module workers, and OffscreenCanvas is required.

## Source

`dist/main.js` — UI and workflow. `dist/settings.js` — defaults and hatching presets. `dist/scenes.js` — scene validation/storage and local model reads. `dist/lenses.js` — camera defaults, lens mappings and tangent transport. `dist/engine.js` — scene, import, geometry analysis integration, and GPU buffers. `dist/navigation.js` — mouse navigation and hold-to-fly camera control. `dist/light-visuals.js` — source icons and direction arrows. `dist/view-drag.js` — camera-plane point dragging. `dist/sigil-data.js` — curve designs, validation and motif presets. `dist/sigil-editor.js` / `dist/sigil.css` — curve editor. `dist/sigil-geometry.js` / `dist/sigil-worker.js` — closed surface generation. `dist/curvature-worker.js` — curvature estimation. `dist/hatch-worker.js` — screen-space line tracing, silhouettes and depth contours. `dist/styles.css` — layout. `server.mjs` — loopback static/file service.

Three.js r180 is bundled under its MIT license; see **THREE-LICENSE.txt**.

`dist/sigil-resolution.js` provides feature sizing and adaptive curve sampling. `dist/sigil-volume.js` handles sparse occupied regions and closed surface extraction. `dist/infinite-grid.js` renders the depth-aware ground plane. `dist/view-compass.js` provides camera axis alignment and roll controls.

`dist/sigil-radius.js` provides the view-aware vertex radius ring and drag mapping. `dist/sigil-presets.js` validates and stores named sigil motifs.

`dist/output-settings.js` validates image dimensions and framing. `dist/output-frame.js` provides camera-preserving image windows and lens field transport. `dist/output-renderer.js` creates independent full-size renders; `dist/output-editor.js` provides the framing preview and export controls.

`dist/toon.js` validates color ramps and supplies interpolation tables; `dist/toon-editor.js` provides the ramp editor; `dist/toon-presets.js` supplies built-in palettes and named color ramp storage. `dist/sigil-smoothing.js` applies angle-protected mesh smoothing with optional volume preservation.

`dist/hard-contours.js` extracts true face-angle creases and depth-tests them. `dist/contour-paths.js` joins visible crease pixels and reserves their screen-space footprint before tracing hatches. `dist/flow-barriers.js` stops tracing across sharp geometry even when contour ink is off.
